# Gravatar behaviors the blueyvatar spec still lacks (v1)

Research for issue #62. Sources are official Gravatar pages only, fetched November 7, 2026. Compared against `docs/spec/blueyvatar-product-spec-v9.md` (sections 5 to 11), `packages/core/src/params.ts`, and `apps/delivery/src/app.ts`. "Not published" means no official page I could reach states it.

| Gravatar behavior | Source | blueyvatar today | Gap | Recommendation |

| Upload formats: JPEG, PNG, HEIC | [Avatars support](https://support.gravatar.com/avatars/) | Blob accepts PNG and JPEG only (spec 5) | No HEIC. Note Gravatar's own docs disagree: the [llms-txt guide](https://docs.gravatar.com/guides/llms-txt/) lists JPG, PNG, GIF | Skip HEIC: atproto avatar blobs are PNG and JPEG, and one file must work in both places. Record the Gravatar doc conflict |

## Notes

- Gravatar's two official sources disagree on upload formats (JPEG/PNG/HEIC on the support page, JPG/PNG/GIF on the llms-txt guide). Treat the support page as user-facing and the guide as API-facing until Gravatar clarifies.
- Not published in any page I read: Gravatar's maximum number of secondary emails, minimum upload dimensions, whether the editor crops, and anonymous API rate limits.
- Explicit reading of the code: `params.ts` accepts `size`, `default`, `forcedefault`, `rating` aliases, and rejects unknown `d` URLs with an error, not a silent fallback.
